# 07 · 流程与踩坑（实操经验）

## Kiro Web
- 浏览器里用的 AI 开发环境，两种模式：**Vibe**（协作、边聊边做）和 **Autonomous**（自主跑任务）。模式只能在新建会话时选，建好不能改。
- 比赛当天可直接在这里用 AI（模型 Opus 5.5）开发，不用另外装 Claude Code。
- 沙盒**不能跑长驻进程**（dev server 等），所以给手机看的公开网址靠 GitHub Pages 等静态托管，不靠沙盒起服务。
- **聊天记录不会自动进仓库。** 对话存在 Kiro 的云端会话里，GitHub 里只有 AI 写成文件并推送的内容。会话 90 天没有活动才过期，打开会话或发消息会重新计时。
- **Kiro 文档没提到网页版能导出聊天。** Kiro IDE 有 Export Chat，Kiro CLI 有 `/chat save`；网页版文档里唯一的办法是让 AI 把对话写成文件。
- **长对话会被自动压缩。** 快到上下文上限时，较早的消息会被换成摘要，之后 AI 就写不出那部分的原文了。想留原文，要每轮当场存。
- **沙盒连不到用户自己的电脑。** 云端会话的命令和工具都在云端执行，从本机的 Kiro 打开云端会话也一样。要让 AI 操作用户电脑上的软件（比如 Unity 编辑器），得在用户电脑上开 Kiro 的本地会话。
- **沙盒里装软件的坑（10-29 装 Blender 时遇到）：** 系统盘只读，不能用 dnf 直接装；`/tmp` 会在会话中途被清空；`/projects` 下除了工作区 `/projects/sandbox` 大多写不进去；download.blender.org 会拦截脚本下载；没有显卡。办法：软件装进工作区里、git 仓库外的 `.tools` 文件夹；缺的系统库下载安装包后自己解压。见 `tools/blender/setup.sh`。
- **AI 开不了 GitHub Pages（10-29 实测）：** 用 API 打开 Pages 返回 403，Kiro Agent 这个 GitHub App 没有 Pages 权限。要用户在仓库 Settings → Pages 里手动开（步骤见 docs/15）。
- **临时链接可以用 raw.githack：** `https://raw.githack.com/用户/仓库/提交号/路径/index.html`。会先出现英文中转页，要点 Open the page；.glb 等文件会被转到 raw.githubusercontent.com（国内常打不开），所以模型要内嵌进 JS；第一次请求大文件可能超时。
- **AI 能用沙盒浏览器打开网页游戏并截图自查**，靠 CPU 模拟画图，帧数偏低；沙盒浏览器没有中文字体，截图里中文是方块。
- 以上前三条的来源：[Cloud sessions](https://kiro.dev/docs/cloud-sessions)、[Using the agent](https://kiro.dev/docs/web/using-the-agent)、[Compaction](https://kiro.dev/docs/compaction)，2026-10-29 查。

## GitHub 连接（实测可用的步骤）
1. 打开 app.kiro.dev → **Settings → Integrations** → **Connect GitHub**。
2. 跳到 GitHub，授权 **Kiro Agent** 这个 App；仓库权限选 **Only select repositories**，勾上目标仓库，**Install & Authorize**。
3. 以前装过就进 GitHub → Settings → Applications → Installed GitHub Apps → Kiro Agent → Configure → Repository access，把新仓库加进去。

实测经验：
- **Kiro 登录号和 GitHub 号可以不是同一个。** 授权的是仓库所在的 GitHub 账号。点 Connect 前先确认浏览器里登录的 GitHub 是对的那个账号。
- 连接前，这个会话里 `gh`/`git push` 都报 `No user principal found`，推不了。
- **连接后同一会话就能推**（不用新建会话）：实测 `git push --dry-run` 和 `gh api` 都通过，对仓库有 admin/push 权限。
- 连接必须本人在自己浏览器点授权，AI 代替不了。

## 提交方式（怎么体现"完整 vibe coding 过程"）
- **每步一个清晰的 commit message**，例如「方块原型：小船移动 + 60 秒倒计时」，而不是「update」。
- 维护一个 **开发日志文件**（记录每阶段做了什么、用户反馈了什么、怎么改），和代码一起提交。评委核验时直接看得懂，比聊天记录有用。
- Kiro 默认**不往 main 直推**，而是推到新分支再开 PR。本练习仓库是空的、本人独有，为了让 GitHub Pages 直接出网址，直接用了 main；比赛仓库按需要走分支/PR。
