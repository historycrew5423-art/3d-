# 03 · 小王子 3D 游戏案例

最近很火的参考作品：**《The Little Prince: Across the Stars》**（小王子：穿越群星），一个开发者 Sac 一个人用 16 天做出来的、浏览器里可玩的 3D 叙事游戏，把书里每颗星球都做成能自由探索的 3D 场景。

- 游戏：https://littleprince.dev/ （需支持 WebGPU 的浏览器）
- 作者：X @Saccc_c
- 来源：[Tripo 官方案例教程](https://www.tripo3d.ai/blog/how-to-build-an-explorable-3d-game-with-tripo-and-ai)、[36氪报道](https://eu.36kr.com/en/p/4027808060101250)

## 它是怎么做出来的（工具链）
1. **Fable 5.1**：整理需求、场景、角色、剧情节奏。
2. **Image 2.5**：生成多角度场景参考图（俯视讲布局、斜侧视讲高度和体积、全景）。
3. **让 AI 判断**哪些物件交给 Tripo 生成，哪些直接在 Blender 建。
4. **Tripo 生成模型**：场景道具用 HD Model；角色先画前后左右四视图 T-pose，再用 Smart Mesh 生成可用于游戏的拓扑。
5. **Opus 5.5 + Blender**：摆场景、对齐参考图，再派一个独立 review agent 从多角度截图和参考图盲评，有差距继续改。
6. **角色动画**：Blender 里用 Auto-Rig Pro（付费插件）绑骨骼和蒙皮，动作来自 Mixamo；像"浇水"这种手要接触物体的动作需要手工精修。
7. **Unity 组装 + Astra 修 bug**：最后在 Unity 里把场景、角色、交互拼成可玩版本。

## 对我有用的部分
**值得学的是这个循环：**
> 参考图 → 列资产清单 → Tripo 生成 → 截图和参考图对比 → 继续改。

把大任务拆成小目标：先建一个场景，让角色在里面动起来，再接更多场景和剧情，边做边测。

## 不值得照搬的部分
- **Blender 绑骨 + Unity + 多场景**整套太重，不适合一天的黑客松，也不适合不写代码、不熟 Blender/Unity 的人。
- **只支持 WebGPU** 会让一部分观众的手机打不开——现场扫码玩的场景下是硬伤。
- 直接做"小王子"有**原创风险**（比赛明令禁止换皮、与已有作品高度相似）。**学流程，别学内容。**

## 一句话总结
一个人 + AI + 3D 工具，确实能把一个想法逐步做成能上手体验的作品。关键不是工具多，而是把任务切小、边做边测、用参考图锁住方向。
