# 04 · 技术路线

## 推荐路线
> **AI（Opus 5.5）写代码 + Three.js + 单文件 HTML，模型用 Tripo 生成，部署到 GitHub Pages。**

### 为什么
- 比赛要交**可访问的游戏网址**，浏览器游戏部署最快，扫码就能玩。
- 单个 `index.html`（Three.js 走 CDN）**不用安装、不用构建**，浏览器直接打开就能跑，对不写代码的人最省心，GitHub Pages 能直接托管。
- 实测经验（[Simon Willison](https://simonw.substack.com/p/the-october-inflection-point-for)）：让模型用 three.js 做游戏效果最好。开头用 `Build a mobile-friendly three.js game where...`，不好玩就补一句 `Make it a LOT more fun`。
- Tripo 官方 [Vibe Gaming Playbook](https://www.tripo3d.ai/zh/tutorials/vibe-gaming) 就是这条路线，分六阶段：设计 → 方块原型 → 资产清单 → 在 Tripo 生成模型 → 换模型 → 发布。他们实测每个游戏 agent 跑 2–3.3 小时、花 $14–47、用 920–1485 Tripo 积分，人在 Tripo 里操作 26–50 分钟（每人 3000 积分够用）。

### 为什么不用 Unity（团结引擎 + Codely）
- 只适合队里有人熟 Unity。WebGL 打包慢、包体大，改完 C# 还要进编辑器看效果，迭代比网页慢很多。我不熟 Unity，不走这条。

## 关键工程结构（从别人项目学到的）
来自 [awesome-opus-5-5-prompts](https://github.com/TripoGrowthLab/awesome-opus-5-5-prompts) 里的 PIT NINE：
> 把所有"长什么样"集中写在一张 **id → 构建函数** 的注册表里。先用方块占位，之后换 Tripo 模型时**不用动玩法代码**。

这条很重要：**先做能玩的方块版，再换模型**。玩法和外观分开，换模型不会把游戏改坏。

## GitHub 上值得看的资源
- [TripoGrowthLab/awesome-opus-5-5-prompts](https://github.com/TripoGrowthLab/awesome-opus-5-5-prompts)：63 个 Opus 5.5 真实项目的 prompt，12 个是游戏。
- [shipshitgames/skills](https://github.com/shipshitgames/skills)：给 Claude Code 用的 3D 网页游戏 skills。**只建议拿 `playwright-game-testing`**（让 AI 自己截图检查画面），别用他们的引擎/模板，免得被算成过度依赖开源。
- [VibeFin/awesome-opus-5.5-games](https://github.com/VibeFin/awesome-opus-5.5-games)、[coolbat/awesome-opus-5.5-usecase](https://github.com/coolbat/awesome-opus-5.5-usecase)：别人做过的游戏清单，用来查点子有没有撞车。

## 沙盒环境（Kiro Web）
- 网络：开放互联网。已装 Node.js（默认 v22）、Python、Go、Rust 等。
- 限制：**不能跑长驻进程**（如 dev server）。所以给手机看的公开网址只能靠 GitHub Pages 这类静态托管，不能靠沙盒里起服务。
