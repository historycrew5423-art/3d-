# 04 · 技术路线（三条路都敞开，按点子和时间选）

前提先说清楚：**有 AI 帮忙，不写代码、不熟 Blender/Unity，并不等于这些路线就走不了。** 下面三条路都在桌面上，各有取舍。先看取舍，启动会后根据定下来的点子再选，不提前锁死。

## 路线 A：网页 / Three.js（单文件 HTML）
- **怎么做：** AI 写代码，Three.js 走 CDN，一个 `index.html`，模型用 Tripo 生成，部署 GitHub Pages。
- **强在：** 不用安装、不用构建，浏览器直接开；**出网址最快，手机扫码即玩**；迭代快（改完刷新就看到）。
- **弱在：** 画面上限不如成熟引擎；复杂物理、大场景、精细光影要自己搭。
- **适合：** 一天的黑客松、要现场扫码试玩、追求"10 秒看懂 + 手机能玩"。实测（[Simon Willison](https://simonw.substack.com/p/the-october-inflection-point-for)）用 three.js 让模型做游戏效果很好。

## 路线 B：Unity（团结引擎 + Codely）
- **怎么做：** Unity 现在有**官方的 Claude Code / Codex / Grok 插件**和官方维护的工程 skills（来源：[Unity AI](https://unity.com/features/ai)），AI 能直接读写 C#、场景文件、看编辑器日志。Unity 自带 AI 生成器能在编辑器里出占位资产。赞助方还给了 **Unity Codely**（团结引擎，Unity 中国版）的权益。
- **强在：** 3D 能力最强，物理/动画/粒子/光照成熟；想做"有质感的 3D"上限高；有官方 AI 工具链和本次赞助额度。
- **弱在：** WebGL 打包慢、包体大；改完 C# 常要进编辑器确认效果，**迭代比网页慢**；要装编辑器、学习面更大（但 AI 能扛掉很多）。
- **适合：** 队里有人愿意边学边上，或点子确实需要 Unity 的能力（复杂物理、成熟动画系统）；也可打包成桌面/网页版现场演示。
- **渲染管线的限制（10-29 查）：** Unity 画质最高的 HDRP 不支持 WebGL、WebGPU，也不支持 iOS 和安卓；网页和手机只能用 URP（URP 支持 WebGPU）。所以"手机扫码玩"的 Unity 版本拿不到 HDRP 画质，HDRP 只适合在电脑上跑。来源：[Unity 渲染管线对比](https://docs.unity.com/en-us/engine/6000.7/manual/render-pipelines/choose-a-render-pipeline/feature-comparison)。
- **注意：** Codely 兑换窗口 10-30 00:00–11-01 00:00，兑换后积分 3 天内有效（官网我没完全打开，细节以现场/权益页为准）。

## 路线 C：Blender + 引擎（小王子那套）
- **怎么做：** 像小王子项目一样，AI 用 Blender 命令行（或 MCP）驱动建模、优化、绑骨，再进 Unity/Godot 组装。
- **强在：** 资产质量最高，场景最讲究。
- **弱在：** 链路最长、最重；绑骨+动作最费时间。
- **适合：** 对画面要求很高、时间和分工撑得住的情况。一天的赛程里风险偏高。

## 怎么选（建议，不是规定）
- **默认先用 A 把"能玩的核心"跑起来**，因为评奖靠现场投票，"好懂 + 手机能玩"最吃香，而 A 出网址最快，第一个小时就能有可玩版本。
- **B / C 不排除。** 如果启动会后定的点子需要更强的 3D 能力，或你愿意试 Unity，就上 B——有官方 AI 插件和 Codely 额度兜底。时间非常充裕且追求画质，再考虑 C。
- **也可以混：** 玩法和框架用 A 快速验证，资产用 Tripo/Blender 做好再按需要迁移。关键是**先有能玩的东西，再加码**。

## 关键工程结构（不管哪条路都适用）
来自 [awesome-opus-5-5-prompts](https://github.com/TripoGrowthLab/awesome-opus-5-5-prompts) 的 PIT NINE：
> 把"长什么样"集中写在一张 **id → 构建函数** 的注册表里。先用方块占位，之后换 Tripo 模型**不用动玩法代码**。

即：**先做能玩的方块版，再换模型**；玩法与外观分离，换模型不会把游戏改坏。

## GitHub 上值得看的资源
- [TripoGrowthLab/awesome-opus-5-5-prompts](https://github.com/TripoGrowthLab/awesome-opus-5-5-prompts)：63 个 Opus 5.5 真实项目 prompt，12 个是游戏。
- [shipshitgames/skills](https://github.com/shipshitgames/skills)：给 Claude Code 用的 3D 网页游戏 skills。建议只拿 `playwright-game-testing`（让 AI 自己截图检查画面），别照搬整套引擎/模板，免得被算成过度依赖开源。
- [VibeFin/awesome-opus-5.5-games](https://github.com/VibeFin/awesome-opus-5.5-games)、[coolbat/awesome-opus-5.5-usecase](https://github.com/coolbat/awesome-opus-5.5-usecase)：别人做过的游戏清单，用来查点子有没有撞车。

## 沙盒环境（Kiro Web）
- 网络开放；已装 Node.js（默认 v22）、Python、Go、Rust 等。
- 限制：**不能跑长驻进程**（dev server 等），所以给手机看的公开网址靠 GitHub Pages 这类静态托管。若走 Unity 本地打包，则在本机/现场机器上跑。
