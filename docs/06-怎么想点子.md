# 06 · 怎么想点子

## 筛选标准（点子要同时满足）
1. **只有一个核心动作**（跳、扔、叠、躲、推、开），看 10 秒就懂。
2. **真的需要 3D**：靠空间、视角或物理才成立，而不是 2D 游戏套个 3D 皮。
3. **一局 1–2 分钟**，有分数或明确结局，方便现场比拼。
4. **主角尽量不需要骨骼动画**：车、球、机器人、由部件拼成的小动物最省事。人形角色的绑骨+动作是最耗时的环节（小王子就卡在这，用了 Blender + Auto-Rig Pro + Mixamo）。Tripo 教程也只给人形加骨骼，其他角色用代码驱动部件来动。
5. **和现场的人有共鸣**：上海元素、vibe coding 圈的梗等，路演好讲、拉票有利。

## 候选点子（只是示范怎么套标准，不是定稿）
- **Token 不够用**：你是一个小机器人 agent，在不断缩小的机房里抢 token、躲 bug，房间大小 = 剩余上下文。圈内梗，路演好讲。
- **渡轮叠蒸笼**：在随浪晃动的黄浦江渡轮上叠小笼蒸笼，塌了就输。一键操作，适合手机。（注意叠高类已有 Stack，要加自己的机制。）
- **漂流瓶小船**：开小船 60 秒收集漂流瓶、躲礁石。主角是船，不用骨骼，最适合练手——见 `08-练习游戏草稿.md`。
- **现场多人对战**：观众扫码进同一房间对战。拉票效果最好，但要做联网，风险最高。

## 原创性提醒
比赛明令：不能换皮、不能过度依赖开源、不能和已上线产品高度相似。
- 可以借鉴**玩法机制**，但要有自己的主题、角色、关卡和一个别人没做过的小转折。
- 做之前去 [VibeFin/awesome-opus-5.5-games](https://github.com/VibeFin/awesome-opus-5.5-games) 查一下有没有撞车。

## 待确认（和 AI 继续聊游戏时要定的）
- 题材/故事：想做什么世界？（用户说"有一点想法，但不多"。）
- 核心动作定哪个？
- 主角是不是人形？（决定要不要碰骨骼动画。）
