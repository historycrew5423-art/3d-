# 01 · 比赛规则要点（挑会影响怎么做的）

来源：VibeHacks #06 参赛者指南（飞书文档）、官网 https://vibecafe.ai/hacks/6

## 硬规则（踩了会被取消资格或奖金）
- **首个 commit 必须在 2026-10-30 18:00 之后。** 之前可以构思、准备工具、建空仓库，但不能先写代码。提前构思不算抢跑。
- **必须原创。** 不能拿旧项目换皮；不能过度依赖开源项目而没有自己的开发；不能和已上线产品高度相似。违反直接撤销奖金。
- **要能体现完整的 Vibe Coding 过程。** 私有 GitHub 仓库要加 **@Glowin** 为协作者，commit 记录要能看出整个过程。
- **以队伍为单位提交，单人也要先建队。** 提交截止 **10-31 18:00**。

## 作品要求
- 用 Vibe Coding 做一个**可玩、可现场演示的 3D 游戏 Demo**。
- 一个小关卡或一套核心交互就够，但**玩家目标、操作、挑战、成功/失败反馈都要清楚**。
- 提交内容：项目名称、介绍、游戏目标/操作/玩法、截图、**可访问的游戏网址**、**GitHub 链接**、小红书链接。

## 评奖方式（决定了该做成什么样）
- **真的会玩奖：** 一等 10000、二等 5000、三等 3000 元。现场投票选出。
- **投票权重：** 特约观察员每人 1 票，参赛者每人 2 票，Mentor 每人 10 票；Mentor 另有一次额外 10 票的"爆灯"机会并说明理由。
- **小红书社区人气奖：** 1000 元，按笔记点赞+收藏计数，统计到 11-06 18:00。

### 推论：作品该优先满足什么
因为投票的人多半只看 3 分钟路演，或现场扫码玩一两分钟：
1. **10 秒能看懂**玩法。
2. **手机能玩**（现场扫码）。
3. **一局 1–2 分钟**，有分数或明确结局，方便对比。
4. 画面精美是加分项，但不如"好懂 + 好玩 + 能上手"重要。

## 路演
- 每组 **3 分钟**。优先展示核心操作和反馈。
- 建议准备**本地版本或录屏**，作为现场网络/设备异常时的备用。

## 建仓库时的坑（重要）
- 如果在 10-30 18:00 之前就建比赛仓库，**不要勾选 README / .gitignore / License** 任何一项——勾了 GitHub 会在建仓库那一刻自动产生一个 commit，时间早于 18:00，违反"首个 commit 在 18:00 之后"。
- 最省心：**到 18:00 之后再建比赛仓库**，或建一个完全空的仓库。

## 任务清单（参赛前五项）
1. 加入参赛者微信群，改群昵称为「昵称 - 小组名称」。
2. 每位队员独立报名并通过审核，在官网建队/入队。
3. 参加 10-30 18:00 线上启动会。
4. 向小代领取 Pass 卡（发微信用带二维码版，发小红书用不带二维码版）。
5. 发布 Build in Public 笔记（带 #VibeHacks #buildinpublic），回传链接。
